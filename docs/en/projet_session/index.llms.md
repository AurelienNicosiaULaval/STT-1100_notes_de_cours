## Before each milestone

Each project submission should be readable by someone who opens the repository without hearing you explain it.

1.  Check the date, submission location and expected file on Brio.
2.  Render the relevant Quarto documents and open the produced HTML files.
3.  Check that the GitHub repository contains useful files and no temporary files.
4.  Reread the question, data, results and limitations as an external reader.
5.  Make sure team contributions are visible and coherent.

## What the project assesses

The project is more open than the challenges. It assesses your ability to make reasoned choices and make them readable.

### Question

Formulate a problem precise enough to guide the analysis.

### Data

Describe source, variables, limitations and important transformations.

### Analysis

Use course tools to explore, visualize, compare and interpret.

### Communication

Make the work understandable for someone discovering the project.

## Data and responsibility

The project asks for real autonomy, but that autonomy comes with responsibility for provenance, rights and data protection.

### Provenance

The source must be identifiable, cited and stable enough to be found again.

### Usage rights

The license or terms should allow use in the course context.

### Sensitive data

Unnecessary personal or identifying information should not be shared in a public repository.

### Limitations

Biases, missing values, filters and important transformations must be explained.
