## Why challenges?

Each challenge targets a concrete skill. The goal is to move from understanding to a visible trace of what you can do.

### Autonomy

You take a skill seen in the module and apply it in a slightly different context.

### Progression

Challenges gradually build the reflexes needed for the project and the exam.

### Communication

The deliverable must be understandable to someone reading your work without being inside your head.

## Types of productions

Formats vary across modules, but they always remain connected to course skills.

### Analysis report

Import, summarize, visualize and interpret a dataset.

### Article or short note

Turn an analysis into a clear message for a defined audience.

### Data cleaning

Document correction, recoding and preparation choices.

### Improved graph

Revise a visualization so it better supports interpretation.

### R function

Automate a repetitive task and make code reusable.

### Video or dashboard

Communicate an analysis in a more interactive or narrative format.

## Workflow

A successful challenge is rarely a long document. It is clear, focused and cleanly rendered.

1.  Identify the expected product.
2.  Reuse module examples that resemble the challenge.
3.  Build a simple first version that works.
4.  Render the file, reread it, then improve clarity.

### Do not over-expand

Answer the instructions before adding secondary analyses.

### Name choices

Briefly explain why a transformation, graph or filter is used.

### Reuse feedback

Each challenge prepares the next one: keep useful corrections in your notes.
