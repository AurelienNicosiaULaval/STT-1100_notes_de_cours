## Pourquoi des défis?

Chaque défi cible une compétence concrète. Le but est de passer de la compréhension à une trace visible de ce que vous savez faire.

### Autonomie

Vous reprenez un geste vu en module et vous l'appliquez dans un contexte légèrement différent.

### Progression

Les défis construisent graduellement les réflexes nécessaires pour le projet et l'examen.

### Communication

Le livrable doit être compréhensible pour une personne qui lit votre travail sans être dans votre tête.

## Types de productions

Les formats changent selon les modules, mais ils restent toujours reliés aux compétences du cours.

### Rapport d'analyse

Importer, résumer, visualiser et interpréter un jeu de données.

### Article ou note courte

Transformer une analyse en message clair pour un lectorat défini.

### Nettoyage de données

Documenter les choix de correction, de recodage et de préparation.

### Graphique amélioré

Réviser une visualisation pour mieux soutenir l'interprétation.

### Fonction R

Automatiser une tâche répétitive et rendre le code réutilisable.

### Vidéo ou tableau de bord

Communiquer une analyse dans un format plus interactif ou narratif.

## Méthode de travail

Un défi réussi est rarement un long document. C'est un document clair, ciblé et rendu proprement.

1.  Identifier le produit attendu.
2.  Reprendre les exemples du module qui ressemblent au défi.
3.  Construire une première version simple qui fonctionne.
4.  Rendre le fichier, relire, puis améliorer la clarté.

### Ne pas trop élargir

Répondre à la consigne avant d'ajouter des analyses secondaires.

### Nommer les choix

Expliquer brièvement pourquoi une transformation, un graphique ou un filtre est utilisé.

### Réutiliser la rétroaction

Chaque défi prépare le suivant: garder les corrections utiles dans vos notes.
